# StkhMonitor

Приложение в строке меню macOS: показывает, работает ли `stkh-client`, есть ли
связь с `guard.profit.local` и поднят ли VPN, — и позволяет всем этим управлять,
не открывая терминал. Умеет запускать и останавливать демона по расписанию и
работает сразу во всех сеансах при быстром переключении пользователей.

## Установка

Скачайте `StkhMonitor.dmg` из
[релизов](https://github.com/brekhov-i/stkh-monitoring/releases) и запустите
**Установить StkhMonitor.pkg**. Нужен пароль администратора.

Пакет ставит приложение для всех пользователей компьютера:

- кладёт `StkhMonitor.app` в `/Applications`;
- пишет `/Library/LaunchAgents/com.ilya.stkhmonitor.plist` — launchd запускает
  приложение в каждом графическом сеансе, поэтому иконка есть у любого
  вошедшего пользователя;
- ставит привилегированный helper системным демоном, чтобы запуск и остановка
  `stkh-client` не спрашивали пароль ни у кого;
- запускает приложение во всех уже открытых сеансах — перезаходить не нужно.

macOS может отказаться открывать пакет («не удалось проверить разработчика»):
правой кнопкой → «Открыть» и подтвердить. Приложение подписано локальным
сертификатом, не Developer ID.

Удаление — `./uninstall.sh` из репозитория.

## Что в меню

**Демон и сеть.** Состояние `stkh-client` (иконка `eye.fill` / `eye.slash`),
доступность `guard.profit.local`, кнопка «Запустить» / «Остановить».

**VPN L2TP/IPSec.** Состояние туннеля, подключение и отключение, а при обрыве —
автопереподключение: три попытки с паузой в 15 секунд, счётчик виден в меню.
Служба по умолчанию берётся первая же L2TP в системе, так что в типовом случае
настраивать нечего. В окне настроек можно выбрать другую службу, задать имя
пользователя, пароль и общий ключ или попробовать импортировать их из системной
конфигурации.

**Автоматизация.** Расписание работы демона: рабочее окно (по умолчанию
9:00–18:00, Пн–Пт), необязательный перерыв, ближайшая граница и расхождение
факта с расписанием. Здесь же — автозапуск приложения (для себя или для всех
пользователей) и установка helper'а.

**Разрешения (stkh-client).** Что `stkh-client` запрашивал через TCC — камера,
микрофон, запись экрана, отслеживание ввода и прочее — с возможностью отозвать.
Полный список читается из `TCC.db` и требует Full Disk Access; без него
показывается короткий список без статусов, отозвать разрешение всё равно можно.

## Несколько пользователей

`stkh-client-agent` лежит в `/Library/LaunchAgents` и загружается в каждый
графический сеанс с `KeepAlive`. Отсюда всё поведение приложения при быстром
переключении пользователей:

- **Остановка действует на все сеансы.** Выгрузка агента только в своём сеансе
  ничего не даёт: launchd соседа поднимет демона обратно. Приложение
  перечисляет активные сеансы по `loginwindow` и выгружает агента в каждом.
- **Управлять можно из любой учётной записи.** Helper — системный демон, его
  ставят один раз; дальше им пользуется любой вошедший пользователь, в том
  числе без прав администратора.
- **Автоподключением VPN занимается только активный сеанс.** Туннель на машине
  один, и фоновый экземпляр иначе поднимал бы то, что активный пользователь
  только что отключил вручную.
- **Расписание у каждого пользователя своё** — оно хранится в его
  `UserDefaults` и применяется независимо от того, кто сейчас за экраном.

## Привилегированный helper

Без helper'а каждый запуск и остановка демона упираются в запрос пароля через
`do shell script … with administrator privileges`. Для расписания это не
годится: в 18:00 нажимать «ОК» в диалоге некому.

Helper слушает Mach-сервис и умеет ровно два действия: запустить или остановить
`stkh-client` и включить или выключить автозапуск приложения во всех сеансах.
Произвольных команд, путей и аргументов он не принимает — пути и список сеансов
определяет сам. Клиента проверяет XPC по требованию к подписи, которое
`build.sh` берёт из фактически подписанного бандла.

Ставится он двумя путями:

| Путь | Как | Подтверждение пользователем |
| --- | --- | --- |
| Пакет `.pkg` | системный демон в `/Library/LaunchDaemons` | не требуется |
| Меню приложения | `SMAppService` | нужен тумблер в «Элементах входа» |

Требуется macOS 13 или новее: на более старых системах нет ни `SMAppService`,
ни проверки подписи клиента, и helper туда не ставится — приложение продолжает
работать через запрос пароля. Само приложение собирается с deployment target
11.0.

После смены сертификата подписи helper придётся переустановить: требование к
клиенту вшито в его бинарник на этапе сборки.

## Сборка из исходников

```bash
./build.sh      # build/StkhMonitor.app — универсальный бинарник, подписанный
./make-dmg.sh   # build/StkhMonitor.dmg с установщиком внутри
./install.sh    # локальная установка для всех пользователей (спросит sudo)
./uninstall.sh  # удаление
```

Подпись приложения берётся из `STKH_SIGNING_IDENTITY`; если переменная не
задана, `build.sh` создаёт и использует локальный самоподписанный сертификат
(`make-cert.sh`). Пакет подписывается, только если задана
`STKH_INSTALLER_IDENTITY` — самоподписанный Installer-сертификат macOS всё равно
не считает доверенным.

## Исходники

| Файл | Что внутри |
| --- | --- |
| `Sources/main.swift` | приложение: строка меню, VPN, разрешения, установка helper'а |
| `Sources/Schedule.swift` | логика расписания без AppKit: окна, перерыв, ближайшая граница |
| `Sources/AutomationWindow.swift` | окно настроек автоматизации |
| `Sources/Shared/DaemonControl.swift` | общий код приложения и helper'а: команды управления, перечисление сеансов, XPC-протокол |
| `Sources/Helper/main.swift` | привилегированный helper |
| `installer/postinstall` | что делает пакет после установки |

`Sources/Shared` компилируется в оба бинарника намеренно: только так команды
управления демоном и описание протокола физически не могут разъехаться между
клиентом и сервером. При изменении helper'а поднимайте `helperProtocolVersion` —
launchd продолжает крутить старый бинарник до перерегистрации, и без версии
рассинхрон был бы невидим.
